# 班车停靠事实

把一趟班车的 GPS 定位点整理成“按站停靠”的到站 / 离站事实，供刷卡数据按站关联。
提供可直接用 Docker Compose 启动的操作网页。

## 快速开始

```bash
docker compose up --build
```

打开 <http://localhost:8000> ，分别上传**站点 CSV** 与**定位 CSV**，点击“生成停靠事实”。
页面右上角或首页可下载样例文件。

停止服务：

```bash
docker compose down
```

> 健康检查：`GET /healthz` 返回 `{"ok": true}`；容器带 `HEALTHCHECK`，以非 root 用户运行。

## 输入格式

### 站点 CSV（按线路顺序）

| 列 | 含义 | 说明 |
| --- | --- | --- |
| 站名 | 站点名称 | 不能为空 |
| 纬度 | 纬度 | -90 ~ 90 |
| 经度 | 经度 | -180 ~ 180 |
| 半径米 | 站圈半径（米） | > 0，可写 `100` 或 `100m` |

行序即线路顺序。每次最多 **6 站**。

```csv
站名,纬度,经度,半径米
起点站,31.2300,121.4700,90
人民广场,31.2390,121.4700,90
```

### 定位 CSV（按时间顺序）

| 列 | 含义 | 说明 |
| --- | --- | --- |
| 时刻 | UTC 时刻 | ISO-8601，如 `2026-11-15T08:00:00Z`；必须**严格递增** |
| 纬度 | 纬度 | -90 ~ 90 |
| 经度 | 经度 | -180 ~ 180 |

每次最多 **40 个点**。

```csv
时刻UTC,纬度,经度
2026-11-15T08:00:00Z,31.230000,121.470000
2026-11-15T08:00:20Z,31.230010,121.470020
```

**兼容性**：UTF-8（含 BOM）或 GB18030；逗号 / 分号 / 制表符分隔；
常见中英文表头（如 `stop,lat,lon`、`站点名称,latitude,longitude`）。
无表头时按固定列序解析并在结果页提示。未带时区的时刻按 UTC 解释。

## 判定规则

1. 用**球面（大圆 / haversine）距离**判断站点圈，距离 ≤ 半径即视为在圈。
2. 同一站圈内**连续至少 2 条**原始定位点才形成一次停靠。
3. 每站最多停靠一次，且停靠的站次**不得倒退**（必须符合线路顺序）。
4. 一个定位点最多归一个站，且同一站归站的点必须**连续**。
5. 目标按字典序：**先最大化停靠站数，再最大化归站点数**。
6. 只有**所有**同等最优归属下该站的到离站时刻都一致，才生成该站**事实**；
   否则标记 **待核**，并列出全部可能的到离站时段。
7. 输入错误或没有任何可用停靠时，只说明原因，**不输出部分事实**。

### 输出

- **停靠事实**：线路站序、站名、到站（UTC）、离站（UTC）、归站点数；可导出 CSV。
- **待核**：说明该站是否在每个最优归属中都停靠，列出所有可能的到离站时段及范围。
- **未停靠**：给出圈内最多连续点数等可核对的理由。
- 页面顶部汇总最优停靠站数、最优归站点数、事实 / 待核 / 未停靠数量。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 上传页面 |
| POST | `/analyze` | 表单提交，返回 HTML 结果页 |
| POST | `/api/analyze` | 返回 JSON：`{"ok": true, "data": {...}}` |
| POST | `/api/export.csv` | 直接下载仅含事实的 CSV |
| GET | `/samples/{stations,positions}.csv` | 样例下载 |
| GET | `/healthz` | 健康检查 |

`/api/analyze` 与 `/api/export.csv` 均需 multipart 字段 `station_file` 与 `position_file`。
输入错误返回 **422**，结构如下（不含任何事实）：

```json
{
  "ok": false,
  "error": {
    "code": "missing_column",
    "message": "站点文件（stations.csv）缺少必需的列：经度。",
    "details": ["识别到的列：站名, 纬度, 半径米"]
  }
}
```

常见 `code`：`empty_file`、`missing_column`、`duplicate_column`、`ambiguous_header`、
`bad_number`、`out_of_range`、`bad_time`、`time_not_increasing`、
`too_many_stops`、`too_many_points`、`no_dwell`、`unsupported_file`。

## 本地开发与测试

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
pytest
```

测试包含一个**穷举交叉校验**：对数百个随机场景枚举所有可行归属，
逐一比对 DP 的最优值、每站可行窗口与“事实 / 待核”判定。

## 设计说明

求解用“站点顺序 × 时间顺序”的前后缀动态规划：

- `F[s][p]`：用第 `s` 站及之后、第 `p` 点及之后的最优 `(站数, 点数)`。
- `G[s][p]`：用前 `s` 站、前 `p` 点的最优 `(站数, 点数)`。

区间 `[a,b]` 属于站点 `s` 的某个最优归属，当且仅当
`G[s][a] + (1, b-a+1) + F[s+1][b+1]` 等于全局最优值。
由此同时得到“该站是否出现在任何最优归属”“是否出现在每个最优归属”以及全部可行窗口。
再判断去掉该站后最优值是否下降，以区分“必然停靠”与“仅在部分归属中停靠”。

复杂度约为 `O(站数 × 点数²)`（点数 ≤ 40、站数 ≤ 6），实际响应在毫秒级。
